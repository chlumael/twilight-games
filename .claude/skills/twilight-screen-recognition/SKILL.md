# 화면 인식·게임 감지 (로드맵 M3~M5)

설계의 원본은 `DESIGN.md` §4(파이프라인), §4.7(빠른 스킵 대응), §5(게임별 화면 정의)다. 구현 전에 해당 절을 읽는다. 이 스킬은 구현할 때 지킬 원칙과 순서를 정리한다.

## 원칙 (사용자와 합의됨)

- **트래커가 화면을 읽고 스스로 판단**하고, 수동 입력은 수정용이다.
- 게임 메모리·통신·계정 로그인은 쓰지 않는다. 화면 캡처만 쓴다.
- 순간적으로 지나가는 화면(연출, 교환 확인창)은 보조 정보다. **결과 요약 화면과 재화 잔액**처럼 사라지지 않는 상태를 기준으로 하고, 잔액으로 다시 계산해 맞춘다.
  - 뽑은 횟수 = 줄어든 티켓 + 줄어든 유료 재화 ÷ 1회 비용
  - 창세의 결정 사용량 = 뽑기 후 원석 − 뽑기 전 원석 + 160 × 원석으로 뽑은 횟수
- 확신이 낮으면 멈추지 않고 **확인 대기**(`Pull.status = "pending"`)로 보낸다. 결과를 놓친 구간은 "빈 구간"으로 둔다.
- 화면 영역은 **창 크기 대비 비율**(0~1)로 정의한다. 기기마다 해상도가 다르다.
- 화면 이미지는 기기 밖으로 보내지 않는다. 확인 대기 항목의 작은 크롭만 저장하고, 확정되면 지운다.

## 안드로이드 구현 순서

1. **M3 게임 감지: 취소됨(2026-11-25).** 안드로이드에서 `UsageStatsManager`(사용 기록 권한)는 쓰지 않는다. 게임은 사용자가 고르고, 화면 인식이 들어오면 화면 내용(배너·재화 영역)으로 어떤 게임인지 판단해 전환한다. PC의 프로세스 감지는 유지.
2. **M4 캡처 + 재화 OCR**: `MediaProjection`(포그라운드 서비스 타입 `mediaProjection` 추가, 매번 사용자 동의 창) → `ImageReader`로 프레임 → 가챠 화면일 때만 작은 영역을 ML Kit Text Recognition(한국어, 기기 내)으로 읽는다. 일반 화면에서는 2~3초에 1번만 확인한다.
3. **M5 결과 인식**: 등급은 색(엔드필드 레버: 보라=4성, 노랑=5성, 빨강=6성 / 원신 유성: 파랑·보라·금색), 개수는 요약 화면 카드 수, 이름은 일러스트 특징값 비교(처음 보는 것은 확인 대기 → 사용자가 고치면 학습). 결과는 웹 쪽 장부(`ledger.ts`)에 `source: "screen"`, `confidence`와 함께 넣는다.

- **확정(사용자, 2026-11-25): 휴대폰과 PC의 가챠 화면은 같다.** 잘 보이게 크기만 조금 다르고 **위치는 같다** → PC 녹화 자료의 배치를 휴대폰에도 그대로 쓴다(영역은 화면 대비 비율로).
- **확정(사용자, 2026-11-25): 게임 안 뽑기 기록 화면은 원신·엔드필드·림버스에 있고, 명일방주에는 없다.** 명일방주는 기록 화면 읽기를 계획하지 않는다.
- 사용자 답변(요약 화면에 이름 없음)과 일치한다. 다만 **원신·명일방주·림버스는 개별 공개 화면에 이름 글자가 있다** → 연출을 다 볼 때는 개별 공개 화면의 글자를 읽고, 스킵하면 요약 화면(카드 수·색)과 재화 변화로 판단한다.
- 깨끗한 녹화를 찾는 검색어: `[UI 연출] <게임> 뽑기`, `<게임> 10연차`, `<게임> 헤드헌팅 6성`. 길이 20초~7분, 제목에 게임 이름이 있는 것만 고른다. 채널 "악덕구"의 `[UI 연출] 원신 뽑기_…`가 가장 깨끗했다(사용자 제보).

출처: 사용자 답변(2026-11-25). 사용자는 연출을 **스킵할 때도 있고 다 볼 때도 있다** → 두 흐름 모두 처리하고 같은 결과를 두 번 세지 않는다.

## 레퍼런스와 테스트

- 좌표·색 기준은 반드시 **사용자 기기의 실제 스크린샷**으로 정한다. 받으면 `references/`가 아니라 테스트 고정 데이터(fixtures)로 저장하되, 공개 저장소에 올려도 되는지 사용자에게 먼저 묻는다(게임 화면 이미지).
- 판별 로직은 스크린샷을 입력으로 받는 순수 함수로 만들어 단위 테스트한다(캡처·OCR과 분리).
- 디자인 참고용 화면은 `twilight-game-reference`의 YouTube 프레임으로 구할 수 있지만 좌표 기준으로는 쓰지 않는다.
