줄(row) id는 넣을 때마다 바뀐다. **넣기 전에 그 표의 지금 줄 id를 확인한다.**

## 1단계: 줄 id 확인

지난 갱신의 응답에 새 줄 id가 나온다(`<row id='.25325' …>`). 같은 세션에서 이어 쓰는 중이면 그 id를 쓴다. 모르면 읽는다:

```json
{"kind": "view", "outline": true}
```

전체 구역과 표 id가 나온다(표 안은 접혀 있다). 표 안의 줄을 보려면:

```json
{"kind": "view", "parentId": "makrxgsx02q.2035"}
```

- `read`의 payload에는 `kind`가 꼭 있어야 한다(`{"view":"outline"}`은 거절된다).
- 요청 기록 표는 줄이 많다. 끝이 잘리면 응답의 `next`를 그대로 다시 보낸다. 마지막 줄 id만 필요하다.

## 2단계: 넣기·바꾸기 (`update`)

표에 줄 넣기 — 칸 수를 표와 똑같이 맞춘다(안 맞으면 거절된다):

```json
{"ops": [{
  "op": "insert",
  "target": {"kind": "blocks", "ids": ["makrxgsx02q.<기준 줄 id>"]},
  "side": "after",
  "source": {"as": "blocks", "from": {"kind": "inline", "content": [
    {"type": "row", "content": [
      {"type": "cell", "content": [{"type": "paragraph", "content": [{"type": "text", "text": "2026-11-26"}]}]},
      {"type": "cell", "content": [{"type": "paragraph", "content": [{"type": "text", "text": "요청 내용"}]}]},
      {"type": "cell", "content": [{"type": "paragraph", "content": [{"type": "text", "text": "처리 내용"}]}]}
    ]}
  ]}}
}]}
```

- 요청 기록: `"side": "after"` + 맨 아래 줄 id.
- 결정 표·버전 표: `"side": "before"` + 맨 위 내용 줄 id.

문단 통째로 바꾸기 — `source`가 아니라 **`with`**, 그리고 `"force": true`:

```json
{"ops": [{
  "op": "replace", "force": true,
  "target": {"kind": "blocks", "ids": ["makrxgsx02q.1161"]},
  "with": {"as": "blocks", "from": {"kind": "inline", "content": [
    {"type": "paragraph", "content": [{"type": "text", "text": "현재 버전: … "}]}
  ]}}
}]}
```

여러 op를 한 번에 보내도 된다(요청 기록 한 줄 + 현재 버전 문단).

응답의 "written_not_proposed" 안내는 정상이다(제안이 아니라 바로 반영했다는 뜻). 사용자가 문서 문장을 "다듬어 달라"고 한 경우에만 제안 방식으로 한다.

## 체크 표시·빠뜨리기 쉬운 칸 (2026-11-27 사용자 지적: 일부 칸만 갱신하고 있었음)

- 체크 목록의 항목을 완료로: `{"op":"set","target":{"kind":"blocks","ids":["<listItem id>"]},"attrs":{"checked":true}}`. 새로 넣는 listItem에 `checked`/`attrs`를 붙여도 **적용되지 않는다** — 넣은 뒤 `set`으로 체크한다.
- 표 칸 글자 바꾸기: 그 칸의 문단 id를 `replace`(force)로.
- 버전을 게시하거나 큰 작업을 끝냈으면 **요청 기록·결정 표만이 아니라** 해야 할 일(사용자·Claude), 로드맵 표, 미확정·확인 필요 표까지 훑고 끝난 것은 체크·글을 고친다.

## 현재 버전 문단에 넣는 것 (순서 고정)

1. `현재 버전: 0.9.x (게시 날짜).`
2. `사용자가 업데이트하라고 할 때만 버전을 올린다.`
3. `다음 업데이트에 모인 것(미게시, 웹앱에는 이미 반영): …`
4. `사용자 확인 대기: …` (사용자가 답해야 풀리는 것)
5. `필요한 스크린샷: …` (있을 때)
6. `다음 작업: …`
7. `남은 과제: R3~R5 …` (DESIGN.md §10의 번호)

새 세션은 이 문단만 읽어도 이어갈 수 있어야 한다.

## 쓰는 법

- 요청 칸: 사용자가 한 말을 줄여서. 처리 칸: 무엇을 했는지 + 게시 여부("코드 반영(미게시)" / "0.9.12로 게시") + 못 한 것.
- 확인된 것과 추정을 섞지 않는다. 추정이면 "추정"이라고 쓴다.
- 사용자가 전에 정한 것을 조사 결과로 바꿨으면 결정 표에 "전의 결정을 바꿈, 사용자 확인 대기"라고 분명히 적는다.
- 사용자 이름·이메일 같은 개인 정보는 적지 않는다.
