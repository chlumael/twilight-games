# 화면 인식 빈칸 목록 (스크린샷 대기)

새 화면 인식(DESIGN.md §4.8, 사용자 규칙 2026-11-26)은 **틀이 채워진 화면부터** 켜진다. 아래 빈칸이 채워지기 전에는 그 게임은 예전 방식(화면 전체 글자 + 재화 차이로 뽑기 감지)으로 돈다.

- 틀 데이터: `data/screens/<게임>.json` — `rect`(위치), `hash`·`rgb`(화면 판단 특징), `template`(문구 틀)이 `null`이면 빈칸.
- 특징값 만들기: `python3 -I scripts/screens/feature.py <스크린샷> <x> <y> <너비> <높이>` (위치는 게임 화면 대비 비율). 스크린샷 파일은 저장소에 넣지 않는다.
- 문구 틀은 스크린샷에 실제로 보이는 글자로만 정한다(`{n}` = 숫자, `{s}` = 글자). 실기에서 확인된 오독만 `fixes`에 넣는다.
- 코드에서 빈칸 목록 뽑기: `profileGaps()` (`src/lib/screen-profile.ts`).

## 빈칸 — 기능

| 항목 | 상태 | 필요한 것 |
|---|---|---|
| 숫자 글꼴 견본 맞추기(규칙 4의 대안) | 미구현 | 실기에서 숫자가 계속 틀리는지 먼저 확인. 견본은 각 PC에만 저장 |
| 엔드필드 재구축 시리즈별 이월 | 미구현(지금은 재구축 전체가 한 스택) | E3에서 배너 이름의 시리즈 표기 형식 |
| 원신 무기 기원 "정해진 무기" | 근사(픽업 무기가 아니면 다음 확정) | 기원 기록에 신각의 길 정보가 없음 — 화면에서 읽을지 결정 필요 |
| 재화 예측(네 게임 월정액·원신 기행) | 0.9.1 완료(DESIGN.md §6-2) | 기행 레벨별 지급 시점, 림버스 월간 광기 공급의 하루 양 확인 |
| 게임 화면 비율(16:9) 가정 | 추정 | 창 비율이 다른 실기 스크린샷 한 장 |
| 원신 기원 기록 서버 주소·지역 시간대 | genshin.py 기준(공식 문서 없음) | 실기에서 한 번 불러와 보기 |
| 휴대폰 적용 | PC 다음 | 휴대폰 글자 인식기(ML Kit)로 따로 맞춤 |
